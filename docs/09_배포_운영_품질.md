## 3. 처음 준비 (P0)

1. GitHub 저장소 만들기 (`aiguidepage`, 비공개)
2. Next.js 프로젝트 생성 (TypeScript, Tailwind, App Router)
3. Vercel에서 GitHub 저장소 가져오기 → 자동 배포 연결
4. Firebase 프로젝트 2개 생성 → 웹 앱 등록
5. Authentication: 구글, 이메일 링크(비밀번호 없는 로그인) 켜기, 허용 도메인 등록
6. Firestore 만들기 (서울), 규칙·색인 배포
   ```bash
   firebase deploy --only firestore:rules,firestore:indexes
   ```
7. 서비스 계정 키 발급 → Vercel 환경변수에만 저장 (파일은 저장소에 두지 않음)
8. 운영자 지정: `npm run grant-admin -- jejuailabs@gmail.com` (해당 계정에 `platformAdmin` 표시)
9. 초기 데이터: `npm run seed` (07 §6)

### Firebase 웹 SDK 연결 — 2026-10-07

- 사용자가 제공한 웹 앱 설정은 로컬 `.env.local`에 저장하고, 저장소에는 빈 `.env.example`만 포함한다. Vercel에도 같은 `NEXT_PUBLIC_FIREBASE_*` 값을 입력한 뒤 다시 배포한다. 이 값은 브라우저용 공개 설정이며 Admin SDK 서비스 계정 키와는 다르다.
- Next.js 클라이언트에서 Firebase 앱을 한 번만 초기화한다. 필수 설정이 없으면 Firebase 연결을 건너뛰고 공개 전시관은 계속 표시한다.
- Analytics는 프로덕션 브라우저에서만 동적으로 불러오고, Measurement ID와 브라우저 지원 여부를 확인한다. 개발 서버에서는 방문 통계를 전송하지 않는다. 분석 초기화 실패가 전시관 화면을 중단시키지 않게 한다.
- 이번 연결 범위는 웹 SDK와 Analytics 초기화다. 로그인·초대·조직 권한·Firestore 읽기/쓰기·보안 규칙 배포는 P2에서 구현·검증한다.
- `NEXT_PUBLIC_*` 값은 빌드 시 브라우저 코드에 포함되므로 Vercel 환경변수를 바꾼 뒤에는 재배포가 필요하다.
- Firebase 12.19.0이 포함한 Firestore의 Node용 gRPC 1.9.16에서 알려진 취약점이 확인되어, 같은 1.x 계열의 1.14.5로 의존성 버전을 고정한다. 현재 브라우저에서는 App·Analytics 모듈만 사용하며 Firestore를 실제 연결할 때 서버 경로도 검증한다.

### Firebase Admin SDK 연결 — 2026-10-07

- `src/lib/firebase/admin.ts`는 `server-only`로 제한하고 Node.js 서버에서만 사용한다. 앱·Auth·Firestore 인스턴스는 실제 호출 시 초기화하며, 키가 없는 공개 전시관 빌드에는 영향을 주지 않는다.
- 서비스 계정의 프로젝트 ID·이메일·비밀키는 `.env.local`과 Vercel의 `FIREBASE_ADMIN_*` 변수로만 관리한다. `NEXT_PUBLIC_` 접두사를 붙이거나 JSON 키 파일을 저장소에 넣지 않는다.
- 비밀키는 PEM 원문 줄바꿈과 환경변수의 `\n` 표기를 모두 지원한다. 설정 누락·형식 오류는 비밀값을 포함하지 않는 오류로 보고한다.
- 자격 증명 확인은 Google 토큰 발급까지만 수행하며, 토큰이나 비밀키를 출력하지 않는다. 사용자·조직 데이터를 읽거나 수정하지 않는다.
- Admin SDK는 Firestore 보안 규칙을 우회하므로, 후속 서버 기능은 각 요청의 사용자·조직 권한을 직접 확인해야 한다. 이번에는 로그인·권한 API나 공개 상태 확인 API를 만들지 않는다.
- 현재 uuid 의존성은 Admin SDK의 Storage가 가져온 gaxios 6.7.1 한 경로이며 `v4()`만 사용한다. uuid 9의 보안 경고를 해결하기 위해 CommonJS와 `v4()`를 지원하는 uuid 11.1.1로 고정한다.

## 4. 요금 확인 사항
| 항목 | 내용 |
|---|---|
| Vercel | 무료(Hobby) 요금제는 **개인·비상업 용도**. 조직에 서비스로 제공하면 Pro 요금제 검토 필요 |
| Firebase 무료(Spark) | 로그인·Firestore는 무료 한도 안에서 사용 가능. 한도는 출시 전 공식 요금표로 재확인 |
| Firebase Storage | 새로 만드는 저장소는 유료(Blaze) 요금제가 필요할 수 있음 → 1차는 이미지를 `public/`에 두고, 조직 로고 업로드가 필요해질 때 결정 |
| Firestore 백업 | 자동 백업·내보내기는 Blaze 필요. 1차는 주기적으로 스크립트로 JSON 백업 |

### 핵심 흐름 테스트 목록 (Playwright)
1. 로그인 전 체험 AI 전시관 → 카드 → 사이트 열기
2. 초대코드 가입 → 조직 첫 화면
3. AI 카드 → 크게 보기 → 뒤로가기로 닫힘
4. 프롬프트 피드 스크롤 → 다음 묶음 로딩
5. 관리자가 게임 끄기 → 멤버 화면에서 게임 탭 없음
6. 다크 모드 + 감귤 테마 + 영어로 바꾼 뒤 새로고침 → 그대로 유지, 깜빡임 없음

### 자동 점검 (GitHub Actions)
- 풀 리퀘스트마다: 형식 검사 → 타입 검사 → 단위 테스트 → 규칙 테스트 → 번역 누락 검사

- 스크린샷: `output/qa/desktop.png`, `desktop-hover.png`, `desktop-detail.png`, `mobile.png`, `mobile-detail.png`, `mobile-dark-english-large.png`.
- 검증 명령: `npm run lint`, `npm run typecheck`, `npm run i18n:check`, `npm run build`, 실행 중인 로컬 서버를 대상으로 `npm run test:e2e`.

- 데스크톱 앱 연결 검증: `tests/desktop-launch.spec.ts`에서 OS 분류, Claude 공식 실행 주소와 설치 링크, 실행 요청 안내·수동 웹 대체, 미확인 서비스와 모바일 숨김을 검사한다. 자동 테스트는 OS 실행을 차단하고 UI 흐름만 확인한다. 실제 네이티브 앱 실행 성공을 의미하지 않는다. 캡처: `output/qa/desktop-app-launch.png`.
- Firebase 추가 후 전체 테스트 12개 통과. `tests/firebase.spec.ts`에서 서버 렌더링 시 미실행, 설정 누락 시 안전한 건너뛰기, 앱·초기화 Promise 재사용을 검사한다. 별도 프로덕션 브라우저 검사에서는 설정 API 응답을 모의 처리하고 Analytics 외부 요청을 차단한 채 초기화 1회와 카드 상세 동작을 확인했다. 실제 Analytics 수집 성공이나 Firebase 인증·DB 권한을 검증한 것은 아니다.
- Admin SDK 추가 검증: `npm run test:admin`의 4개 테스트(설정 없는 지연 초기화, 비밀값을 제외한 오류, PEM 줄바꿈·인스턴스 재사용, server-only 경계)와 빌드·타입·린트 통과. `npm run firebase:check`로 Google 토큰 발급을 확인했고 사용자·DB 데이터에는 접근하지 않았다. 저장소 대상 소스와 브라우저·HTML·RSC 산출물에 실제 비밀키가 포함되지 않은 것을 별도로 확인했다.
- `npm audit --omit=dev`: 운영 의존성 취약점 0건. 개발용 ESLint의 `braces` 전이 의존성 경고 5건은 남아 있으며, 현재 audit의 자동 제안은 Next ESLint 설정을 14버전으로 낮추는 변경이라 적용하지 않았다. 운영 배포 전 호환되는 수정 버전을 재확인한다.
- 로컬 원본 `바탕화면/AI바로가기.html`을 지정 경로에서 찾지 못해, 현재 9종 공개 샘플만 사용한다. 23종 데이터 이전은 아직 하지 않았다.
