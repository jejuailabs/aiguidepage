## 2. 환경 구성

| 환경 | 주소 | Firebase 프로젝트 | 용도 |
|---|---|---|---|
| 로컬 | `localhost:3000` | 에뮬레이터 또는 개발용 | 개발 |
| 미리보기 | Vercel 브랜치별 주소 | `aiguide-dev` | 단계별 확인 |
| 운영 | 정식 주소 | `aiguide-prod` | 실제 사용 |

- Firebase 프로젝트를 **개발용 / 운영용 2개**로 분리 → 테스트 데이터가 실제 조직에 섞이지 않게
- Firestore 위치: `asia-northeast3` (서울) — 한 번 정하면 못 바꿈
- ⚠ 이메일 링크 로그인·구글 로그인은 Firebase에 **허용 도메인** 등록이 필요하고 와일드카드가 안 됨 → 브랜치마다 바뀌는 미리보기 주소에서는 로그인이 안 될 수 있음. 고정 미리보기 주소(예: `dev.○○` 또는 Vercel 고정 별칭) 하나를 정해서 등록

## 3. 처음 준비 (P0)

1. GitHub 저장소 만들기 (`aiguidepage`, 비공개)
2. Next.js 프로젝트 생성 (TypeScript, Tailwind, App Router)
3. Vercel에서 GitHub 저장소 가져오기 → 자동 배포 연결
4. Firebase 프로젝트 2개 생성 → 웹 앱 등록
5. Authentication: 구글, 이메일 링크(비밀번호 없는 로그인) 켜기, 허용 도메인 등록
6. Firestore 만들기 (서울), 규칙·색인 배포
   ```bash
   firebase deploy --only firestore:rules,firestore:indexes
   ```
7. 서비스 계정 키 발급 → Vercel 환경변수에만 저장 (파일은 저장소에 두지 않음)
8. 운영자 지정: `npm run grant-admin -- jejuailabs@gmail.com` (해당 계정에 `platformAdmin` 표시)
9. 초기 데이터: `npm run seed` (07 §6)

## 4. 요금 확인 사항
| 항목 | 내용 |
|---|---|
| Vercel | 무료(Hobby) 요금제는 **개인·비상업 용도**. 조직에 서비스로 제공하면 Pro 요금제 검토 필요 |
| Firebase 무료(Spark) | 로그인·Firestore는 무료 한도 안에서 사용 가능. 한도는 출시 전 공식 요금표로 재확인 |
| Firebase Storage | 새로 만드는 저장소는 유료(Blaze) 요금제가 필요할 수 있음 → 1차는 이미지를 `public/`에 두고, 조직 로고 업로드가 필요해질 때 결정 |
| Firestore 백업 | 자동 백업·내보내기는 Blaze 필요. 1차는 주기적으로 스크립트로 JSON 백업 |

## 5. 품질 검사

| 검사 | 도구 | 언제 |
|---|---|---|
| 형식·문법 | ESLint, TypeScript | 저장할 때 · 배포 전 |
| 부품 단위 테스트 | Vitest | 배포 전 |
| **보안 규칙 테스트** | Firebase 에뮬레이터 + rules-unit-testing | 규칙 바꿀 때마다 (07 §4 목록) |
| 핵심 흐름 테스트 | Playwright | 단계 완료 시 |
| 번역 누락 | `npm run i18n:check` | 배포 전 |
| 접근성 | axe (Playwright 안에서) | 단계 완료 시 |
| 색 대비 | 8가지 테마 조합 자동 검사 스크립트 | P1, 색 바꿀 때 |

### 핵심 흐름 테스트 목록 (Playwright)
1. 로그인 전 체험 AI 전시관 → 카드 → 사이트 열기
2. 초대코드 가입 → 조직 첫 화면
3. AI 카드 → 크게 보기 → 뒤로가기로 닫힘
4. 프롬프트 피드 스크롤 → 다음 묶음 로딩
5. 관리자가 게임 끄기 → 멤버 화면에서 게임 탭 없음
6. 다크 모드 + 감귤 테마 + 영어로 바꾼 뒤 새로고침 → 그대로 유지, 깜빡임 없음

### 자동 점검 (GitHub Actions)
- 풀 리퀘스트마다: 형식 검사 → 타입 검사 → 단위 테스트 → 규칙 테스트 → 번역 누락 검사
- 통과해야 합치기 가능

### 로컬 UI 검증 기록 — 2026-10-07

- UI 핵심 흐름 6개 통과: 데스크톱 롤오버·키보드·뒤로가기·공유 URL, 검색·분류, 360/390/768/1024/1440px 반응형, 설정 저장·영어·모바일 큰 글자, 접근성·8가지 주 버튼 대비, 움직임 줄이기.
- 스크린샷: `output/qa/desktop.png`, `desktop-hover.png`, `desktop-detail.png`, `mobile.png`, `mobile-detail.png`, `mobile-dark-english-large.png`.
- 검증 명령: `npm run lint`, `npm run typecheck`, `npm run i18n:check`, `npm run build`, 실행 중인 로컬 서버를 대상으로 `npm run test:e2e`.
- 실제 휴대폰 실기·Safari 검증과 로그인·Firestore 보안 규칙 검증은 후속 단계다. 이번 테스트는 Chromium에서 수행했다.
- 데스크톱 앱 연결 검증: `tests/desktop-launch.spec.ts`에서 OS 분류, Claude 공식 실행 주소와 설치 링크, 실행 요청 안내·수동 웹 대체, 미확인 서비스와 모바일 숨김을 검사한다. 자동 테스트는 OS 실행을 차단하고 UI 흐름만 확인한다. 실제 네이티브 앱 실행 성공을 의미하지 않는다. 캡처: `output/qa/desktop-app-launch.png`.
- `npm audit --omit=dev`: 운영 의존성 취약점 0건. 개발용 ESLint의 `braces` 전이 의존성 경고 5건은 남아 있으며, 현재 audit의 자동 제안은 Next ESLint 설정을 14버전으로 낮추는 변경이라 적용하지 않았다. 운영 배포 전 호환되는 수정 버전을 재확인한다.
- 로컬 원본 `바탕화면/AI바로가기.html`을 지정 경로에서 찾지 못해, 현재 9종 공개 샘플만 사용한다. 23종 데이터 이전은 아직 하지 않았다.
