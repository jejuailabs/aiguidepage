# 03. 전시관 엔진·진열 방식

> 관련: ORCHESTRATION D3 · 04 AI 전시관 · 05 프롬프트·도구·게임 · 07 데이터 모델

## 1. 핵심 개념: 세 가지를 분리한다

```
진열 방식 (layout)      코드로 만드는 부품     shelf · feed · pegboard · arcade
콘텐츠 종류 (type)      코드로 만드는 부품     ai · prompt · tool · game
전시관 (hall)           데이터                 = 이름 + 아이콘 + 진열 방식 + 콘텐츠 종류 + 순서
```

- 새 **조직**, 새 **콘텐츠**, 기존 부품 조합의 새 **전시관** → 데이터만 추가 (코드 수정 없음)
- 새 **진열 방식**이나 새 **콘텐츠 종류**만 코드 추가가 필요하고, 그 경우도 **등록부에 한 줄** 추가하는 방식

## 2. 등록부 (Registry)

```ts
// src/components/layouts/registry.ts
export const layouts = {
  shelf:    ShelfLayout,
  feed:     FeedLayout,
  pegboard: PegboardLayout,
  arcade:   ArcadeLayout,
} satisfies Record<string, HallLayout>;

// src/components/item/registry.ts
export const itemTypes = {
  ai:     { Card: AiCard,     Stage: AiStage,     Detail: AiDetail },
  prompt: { Card: PromptCard, Stage: PromptStage, Detail: null },
  tool:   { Card: ToolCard,   Stage: ToolStage,   Detail: ToolDetail },
  game:   { Card: GameCard,   Stage: GameStage,   Detail: null },
} satisfies Record<ItemType, ItemTypeParts>;
```

- 데이터에 등록부에 없는 이름이 오면: 그 전시관은 숨기고 운영자 화면에 경고 (화면이 깨지지 않게)

## 3. 공통 약속 (모든 진열 방식이 지켜야 함)

```ts
interface HallLayoutProps {
  hall: Hall;                 // 전시관 정보 (이름, 진열 방식 옵션)
  items: Item[];              // 이미 불러온 콘텐츠
  hasMore: boolean;           // 더 불러올 게 있는지 (피드용)
  loadMore: () => void;       // 다음 묶음 불러오기
  onOpen: (item: Item) => void; // 카드 클릭 → 크게 보기
}
```

### 모든 전시관 공통 동작 — "카드 → 크게 보기 → 실행"
1. **카드**: 진열 방식마다 모양은 다르지만, 누르면 항상 `onOpen`
2. **크게 보기 (Stage)**: 공통 무대 위에 콘텐츠 종류별 내용
   - 왼쪽(휴대폰은 아래): 제목 + 한 줄 설명 + 태그
   - 가운데: 카드가 커진 모습 (또는 도구·게임 실행 화면)
   - 버튼: 주 버튼 1개(검은 알약) + 보조 버튼 (`자세히`, `즐겨찾기`)
   - 주소가 `/…/{hall}/{item}`으로 바뀜 → 뒤로가기로 닫힘
3. **자세히 (Detail)**: 크게 보기 안에서 아래로 펼쳐지는 상세 설명 (새 화면으로 넘어가지 않음)

→ 사용자는 **한 전시관에서 배운 방법을 다른 전시관에서도 그대로** 씁니다.

## 4. 진열 방식 4종

### 4-1. `shelf` 선반 (AI 전시관)
- 하얀 선반 위에 정사각 카드 진열, 원본 Shopify Editions와 가장 가까움
- 한 선반당 카드 수: 데스크톱 5 · 태블릿 3 · 휴대폰 2 (휴대폰에서는 선반을 가로로 밀어서 보기도 가능)
- 카드가 선반 위에 "서 있는" 느낌: 바닥에 그림자, 살짝씩 다른 높이(±4px)로 자연스럽게
- 하단 바: 원본의 연도 타임라인 자리 → **카테고리 바** (예: 대화 · 검색 · 문서 · 영상 · 음악), 누르면 해당 카드들만 남고 나머지는 흐려짐
- 옵션: `perShelf`(선반당 개수), `groupBy`(카테고리 기준)

### 4-2. `feed` 피드 (프롬프트 전시장)
- 세로 한 줄(휴대폰) / 가운데 정렬 2줄(데스크톱) 카드가 계속 이어짐
- 끝에 닿기 직전 자동으로 다음 묶음 로딩 (05 참고), 로딩 중엔 회색 뼈대 카드 3개
- 위에 필터 칩 (글쓰기 · 이미지 · 영상 · 업무 · 생활), 고르면 처음부터 다시 로딩
- 배경: 조명 없이 평평한 `--bg`, 카드는 `--surface` 흰 패널 (SNS 느낌)

### 4-3. `pegboard` 공구 벽 (AI 도구)
- 구멍 뚫린 판(점 무늬 배경) 위에 도구가 걸린 모양, 카드 위쪽에 작은 고리
- 카드: 아이콘 크게 + 도구 이름
- 크게 보기 = "작업대": 카드가 아래로 내려오며 커지고 그 안에서 **도구가 바로 실행됨**
- 배경: 따뜻한 회색, 점 무늬는 `--line` 색으로 옅게

### 4-4. `arcade` 오락실 (게임)
- 오락기 모양 카드가 가로로 줄지어 있음, 화면 부분에 게임 미리보기 그림
- 이 전시관만 **다크 모드처럼 어두운 배경**을 기본으로 (라이트 모드여도 오락실 안은 어둡게), 강조색은 네온처럼 빛나게
- 크게 보기 = 오락기 화면이 커지며 게임 시작, [처음부터] [나가기]

### 전시관 분위기 정리
| 진열 방식 | 배경 | 카드 | 크게 보기 |
|---|---|---|---|
| shelf | 밝은 벽 + 조명 | 정사각 커버 | 가운데로 튀어나옴 |
| feed | 평평한 배경 | 흰 패널 | 패널이 펼쳐짐 |
| pegboard | 점 무늬 판 | 걸린 도구 | 작업대로 내려옴 |
| arcade | 어두운 오락실 | 오락기 | 화면이 커짐 |

> 분위기는 달라도 **상단 메뉴, 글꼴, 버튼, 크게 보기 순서는 모두 같습니다.**

## 5. 데이터 불러오기

```
전시관 페이지 진입
 → 그 조직의 전시관 설정 읽기 (진열 방식, 콘텐츠 종류)
 → 공통 콘텐츠 + 조직 전용 콘텐츠를 각각 읽어서 합침 (07 참고)
 → 조직의 숨김·순서 설정 적용
 → 진열 방식 부품에 넘김
```
- 선반·공구 벽·오락실: 한 번에 전부 (수십 개 수준)
- 피드: 12개씩 끊어서 (05 참고)

## 6. 새 전시관 추가 예시

**"교육 영상관"을 피드 방식으로 추가하고 싶다**
1. 콘텐츠 종류 `video`가 없으면 → 코드: `itemTypes`에 `video` 부품 등록 (카드·크게 보기)
2. 데이터: 전시관 `{ key: 'videos', layout: 'feed', type: 'video', title: {ko:'교육 영상관'} }` 추가
3. 데이터: 콘텐츠 추가 → 조직 관리자 화면에서 켜기

**"AI를 피드로도 보고 싶다"** → 코드 수정 없이 2·3번만.
