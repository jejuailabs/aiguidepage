# 07. 데이터 모델·보안 규칙 (Cloud Firestore)

> 관련: 03 전시관 엔진 · 06 권한 · 08 다국어 (번역 필드) · 09 배포 (규칙 배포·테스트)

## 1. 전체 구조

```
hallTemplates/{key}              전시관 원본 (운영자 관리)        ai · prompts · tools · games
items/{itemId}                   공통 콘텐츠 (운영자 관리)
orgs/{orgId}                     조직
  ├─ members/{uid}               멤버 + 권한
  ├─ halls/{key}                 이 조직의 전시관 (원본 복사 + 켜기/끄기·순서·이름)
  ├─ items/{itemId}              이 조직 전용 콘텐츠
  └─ overrides/{itemId}          공통 콘텐츠를 이 조직에서 숨기기·순서 바꾸기
invites/{code}                   초대코드 (서버만 생성·사용)
users/{uid}                      내 정보·보기 설정·내 조직 목록
  └─ favorites/{itemId}          즐겨찾기
events/{autoId}                  (선택) 사용 기록: 열기·복사
```

**공통 콘텐츠와 조직 전용 콘텐츠를 다른 위치에 두는 이유**: 보안 규칙을 단순하게 만들기 위해서입니다. "공통은 로그인한 누구나, 조직 전용은 그 조직 멤버만" 규칙이 위치만으로 결정됩니다.

## 2. 문서 형태

### 2-1. 번역 필드 (08 참고)
```ts
type L10n = { ko: string; en?: string; ja?: string; zh?: string };   // ko 필수
```

### 2-2. 조직 `orgs/{orgId}`
```ts
{
  slug: 'jeju-a',              // 주소용 영문 이름 (고유)
  name: L10n,
  logoUrl?: string,
  theme: { palette: 'gallery'|'ocean'|'tangerine'|'forest', mode?: 'light'|'dark' },
  defaultLocale: 'ko', locales: ['ko','en'],
  status: 'active'|'suspended',
  createdAt, updatedAt
}
```

### 2-3. 멤버 `orgs/{orgId}/members/{uid}`
```ts
{ role: 'admin'|'member', displayName, email, joinedAt, invitedBy?: string }
```

### 2-4. 전시관 `orgs/{orgId}/halls/{key}` (원본 `hallTemplates/{key}`와 같은 형태)
```ts
{
  key: 'ai', layout: 'shelf'|'feed'|'pegboard'|'arcade', itemType: 'ai'|'prompt'|'tool'|'game',
  title: L10n, icon: 'sparkles', order: 1, enabled: true,
  options?: { perShelf?: number, filters?: string[] }   // 진열 방식별 옵션
}
```
- 조직 생성 시 `hallTemplates`를 복사해서 만듦 → 조직마다 자유롭게 바꿔도 원본은 그대로

### 2-5. 콘텐츠 `items/{id}` · `orgs/{orgId}/items/{id}` (공통 형태)
```ts
{
  type: 'ai'|'prompt'|'tool'|'game',
  slug: 'claude',                 // 주소용 (/ko/o/jeju-a/ai/claude)
  title: L10n, summary: L10n,     // 이름, 한 줄 설명
  body?: L10n,                    // 상세 설명 (마크다운)
  category?: string, tags?: string[],
  iconUrl?: string, coverUrl?: string, color?: string,
  order: number,
  status: 'draft'|'published'|'archived',
  public?: boolean,               // 공통 콘텐츠만: 로그인 전 체험판에 보일지
  data: AiData | PromptData | ToolData | GameData,
  createdAt, updatedAt, updatedBy
}
```

종류별 `data`:
```ts
AiData     = { url, appScheme?, appInstallUrl?, promptUrlTemplate?, launchCheckedAt?,
               features: L10nList, examples: L10nList, pricing: L10n, korean: L10n }
PromptData = { aiSlug, text: L10n, variables?: { key, label: L10n }[], resultImageUrl?, resultText?: L10n }
ToolData   = { toolKey: 'prompt-builder'|'char-count'|..., config?: object }
GameData   = { gameKey: 'memory-match'|'ai-quiz'|'2048', config?: object }
type L10nList = { ko: string[]; en?: string[]; ja?: string[]; zh?: string[] }
```
- 저장 전 검사: 화면·서버 모두 같은 검사 규칙(zod 스키마, `src/lib/schema.ts`)을 사용

### 2-6. 조정 `orgs/{orgId}/overrides/{itemId}`
```ts
{ hidden?: boolean, order?: number }
```

### 2-7. 초대 `invites/{code}`
```ts
{ orgId, role: 'admin'|'member', expiresAt, maxUses, uses, createdBy, active: true }
```

### 2-8. 사용자 `users/{uid}`
```ts
{
  displayName, email, orgIds: string[], lastOrgId?,
  prefs: { locale?, mode?: 'light'|'dark'|'system', palette?, fontScale?: 1|1.15|1.3 },
  createdAt
}
```

## 3. 읽어오는 방법

전시관 화면 하나를 그릴 때:
```
① orgs/{org}/halls/{hall}                  전시관 설정
② items         where type==X, status=='published'  order by order    공통
③ orgs/{org}/items  where type==X, status=='published'  order by order 조직 전용
④ orgs/{org}/overrides                      숨김·순서
→ ②+③ 합치고 ④ 적용 → 순서대로 정렬
```
- 피드(프롬프트)는 ②·③을 각각 12개씩 커서로 끊어 읽고 섞어서 보여줌
- 로그인 전 체험판: ②에 `public==true` 조건 추가 (규칙이 그 조건을 요구함)

### 필요한 색인 (`firestore.indexes.json`)
| 컬렉션 | 필드 |
|---|---|
| `items` | `status` ↑, `type` ↑, `order` ↑ |
| `items` | `status` ↑, `public` ↑, `type` ↑, `order` ↑ |
| `items` (조직 하위) | `status` ↑, `type` ↑, `order` ↑ |

## 4. 보안 규칙 (`firestore.rules`) 초안

```
rules_version = '2';
service cloud.firestore {
  match /databases/{db}/documents {

    function signedIn()          { return request.auth != null; }
    function platformAdmin()     { return signedIn() && request.auth.token.platformAdmin == true; }
    function memberDoc(orgId)    { return /databases/$(db)/documents/orgs/$(orgId)/members/$(request.auth.uid); }
    function isMember(orgId)     { return signedIn() && exists(memberDoc(orgId)); }
    function isOrgAdmin(orgId)   { return isMember(orgId) && get(memberDoc(orgId)).data.role == 'admin'; }
    function onlyChanges(keys)   { return request.resource.data.diff(resource.data).affectedKeys().hasOnly(keys); }

    // 전시관 원본: 누구나 읽기(로그인 전 체험판에도 필요), 운영자만 쓰기
    match /hallTemplates/{key} {
      allow read: if true;
      allow write: if platformAdmin();
    }

    // 공통 콘텐츠: 공개 체험분은 누구나, 나머지는 로그인한 사람
    match /items/{id} {
      allow read: if platformAdmin()
                  || (resource.data.status == 'published' && (resource.data.public == true || signedIn()));
      allow write: if platformAdmin();
    }

    match /orgs/{orgId} {
      allow read: if isMember(orgId) || platformAdmin();
      allow update: if platformAdmin()
                    || (isOrgAdmin(orgId) && onlyChanges(['name','logoUrl','theme','defaultLocale','locales','updatedAt']));
      allow create, delete: if platformAdmin();

      match /members/{uid} {
        allow read: if (signedIn() && request.auth.uid == uid) || isOrgAdmin(orgId) || platformAdmin();
        allow create: if false;                                  // 가입은 서버(초대코드)만
        allow update: if platformAdmin()
                      || (isOrgAdmin(orgId) && request.auth.uid != uid && onlyChanges(['role']));
        allow delete: if platformAdmin() || (isOrgAdmin(orgId) && request.auth.uid != uid);
      }

      match /halls/{key} {
        allow read: if isMember(orgId) || platformAdmin();
        allow write: if isOrgAdmin(orgId) || platformAdmin();
      }

      match /items/{id} {
        allow read: if isOrgAdmin(orgId) || platformAdmin()
                    || (isMember(orgId) && resource.data.status == 'published');
        allow write: if isOrgAdmin(orgId) || platformAdmin();
      }

      match /overrides/{id} {
        allow read: if isMember(orgId) || platformAdmin();
        allow write: if isOrgAdmin(orgId) || platformAdmin();
      }
    }

    // 초대코드: 그 조직 관리자만 목록 보기, 생성·사용은 서버만
    match /invites/{code} {
      allow read: if isOrgAdmin(resource.data.orgId) || platformAdmin();
      allow write: if false;
    }

    match /users/{uid} {
      allow read: if signedIn() && request.auth.uid == uid;
      allow create: if signedIn() && request.auth.uid == uid && request.resource.data.orgIds.size() == 0;
      allow update: if signedIn() && request.auth.uid == uid
                    && onlyChanges(['displayName','prefs','lastOrgId','updatedAt']);   // orgIds는 서버만
      match /favorites/{id} {
        allow read, write: if signedIn() && request.auth.uid == uid;
      }
    }

    match /events/{id} {
      allow create: if signedIn() && request.resource.data.uid == request.auth.uid;
      allow read: if platformAdmin();
    }
  }
}
```

**주의 — 규칙은 걸러주는 기능이 아닙니다.** 멤버가 조직 전용 콘텐츠를 읽을 때 쿼리에 반드시 `status == 'published'` 조건을 넣어야 합니다. 조건이 없으면 규칙이 쿼리 전체를 거부합니다. 로그인 전 체험판은 `public == true` 조건도 필요합니다.

### 규칙 테스트 (P2 완료 조건)
Firebase 에뮬레이터 + `@firebase/rules-unit-testing`으로 최소 아래를 확인:
- [ ] A 조직 멤버가 B 조직의 `orgs/B`, `orgs/B/items` 읽기 → **거부**
- [ ] 멤버가 자기 권한을 `admin`으로 바꾸기 → 거부
- [ ] 사용자가 `users/{uid}.orgIds`에 조직 추가 → 거부
- [ ] 로그인 안 한 사람이 `public != true`인 공통 콘텐츠 읽기 → 거부
- [ ] 조직 관리자가 자기 조직 콘텐츠 쓰기 → 허용, 다른 조직 → 거부

## 6. 초기 데이터 이전 (`seed/`)
- 원본: `바탕화면\AI바로가기.html` 안의 `AIS` 목록(23종)과 내장 아이콘
- 변환 스크립트 `seed/extract-from-html.ts`:
  1. HTML에서 `AIS`, `ICONS`를 읽음
  2. 아이콘(내장 그림 데이터)을 `public/icons/ai/{slug}.png` 파일로 저장
  3. 필드 매핑: `n→title.ko`, `s→summary.ko`, `u→data.url`, `f→data.features.ko`, `e→data.examples.ko`, `p→data.pricing.ko`, `k→data.korean.ko`, `col→color`, 카테고리→`category`
  4. `seed/items.ai.json` 생성 → 검토 후 `npm run seed`로 Firestore에 올림
- 1차 노출 9종은 `status:'published'`, 나머지 14종은 `status:'draft'`
- 전시관 원본 4개(`hallTemplates`)와 테스트 조직 A·B도 같은 스크립트로 생성
